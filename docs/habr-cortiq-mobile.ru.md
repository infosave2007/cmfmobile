# Локальный AI на iPhone: 145,7 tok/s на LFM2.5 230M в Cortiq Mobile

Локальная модель на телефоне перестала быть демонстрацией «смотрите, она запустилась». Cortiq Mobile может превратить смартфон в локальный чат, переводчик, рабочее место для текстовых документов или API в доверенной сети — модель и сценарий выбираются под задачу.

Проверили это на подключённом **iPhone 16 (A18)** с TestFlight-сборкой **1.3.0 (47)**. Компактная `lfm2.5-230m-q4tp` в трёх тёплых прогонах показала **144,5–166,0 tok/s**, медиана — **145,7 tok/s**. Это показатель, который чат Cortiq показывает для данной генерации. Переключатель GPU был выключен, пул CPU — `Auto (5)`.

Практический результат: короткие локальные ответы появляются без привычной паузы большой модели. Не нужно отправлять запрос в обязательный удалённый inference endpoint — если модель уже скачана и не включены Companion или Oracle.

![LFM2.5 230M Q4TP on iPhone — 162.1 tok/s in the Cortiq chat](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/15_lfm230_iphone_speed.png)

*Реальный экран iPhone: интерфейс показывает `lfm2.5-230m-q4tp`, 95 токенов ответа, 0,6 с и 162,1 tok/s. Задержка в UI округлена.*

**Приложение:** [Google Play](https://play.google.com/store/apps/details?id=ai.cortiq.cmf_mobile) · **исходный код 1.3.0:** [infosave2007/cmfmobile](https://github.com/infosave2007/cmfmobile/tree/v1.3.0) · **английская страница со скриншотами:** [Hugging Face Space](https://huggingface.co/spaces/infosave/cortiq-mobile)

> Материал подготовлен командой Cortiq. Версии моделей, методики и сырые наблюдения открыты по ссылкам в конце. iPhone-результаты и снимки относятся к TestFlight 1.3.0 (47); ссылка Google Play ведёт на публичную Android-страницу.

## Четыре рабочих сценария

**1. Быстрый локальный чат.** Загрузите небольшую чат-модель — например, LFM2.5 230M — и получите потоковый ответ с показателями задержки, входных и выходных токенов, `tok/s`.

**2. Перевод без обязательного облака.** Отдельная Hy-MT2 1.8B работает на устройстве после загрузки модели. В проверке были RU, EN, DE, TR и ZH.

**3. Чат с текстовыми вложениями.** Для совместимой чат-модели с шаблоном чата и контекстом от 2048 токенов можно прикладывать текстовые файлы до 512 KiB: `txt`, `md`, код, JSON и другие текстовые форматы.

**4. API в кармане.** После ручного запуска сервера с загруженной чат-моделью доступны `/v1/chat/completions`, `/v1/completions` и `/v1/models`. При загруженной CMF Decision-модели доступны типизированные `/v1/decide`, `/v1/decisions` и `/v1/skills`. Ноутбук подключается привычным OpenAI-совместимым клиентом; в приложении есть QR-код адреса, журнал запросов и bearer-аутентификация.

Одновременно в память загружена одна активная модель: чат, перевод и Decision — это выбираемые режимы телефона, а не три параллельных процесса.

## 145,7 tok/s в чат-UI: как измеряли

Здесь важна не абстрактная «скорость iPhone», а конкретная связка устройства, модели и сценария.

| Параметр | Наблюдение |
|---|---|
| Устройство и сборка | iPhone 16 (A18), TestFlight 1.3.0 (47) |
| Модель | `lfm2.5-230m-q4tp`, 126 MiB, 14 слоёв |
| Три тёплых прогона | **144,5**, **145,7**, **166,0 tok/s** |
| Медиана | **145,7 tok/s** |
| Настройки | `temperature: 0.10`, `top_p: 0.95`, `max_tokens: 128`, CPU `Auto (5)`, GPU toggle off |

Методика проста: новый пустой чат, встроенный запрос `Explain how CMF task masks work`, один прогрев и три `regenerate` в одной UI-сессии. Интерфейс показывал семь токенов входа на каждом наблюдении.

`tok/s` здесь — отображаемые приложением токены ответа, делённые на полный интервал выполнения, который движок измеряет после старта генерации. В него входят обработка промпта и ответ модели; ожидание в очереди не входит. Задержку UI округляет, а `tok/s` рассчитывается по неокруглённому таймеру. Это замер отзывчивости и пропускной способности, а не оценка качества ответа на вопрос о task masks.

Для этой проверки **60 tok/s** — выбранная практическая отметка короткого чата, а не отраслевой норматив. Все три тёплых прогона LFM оказались выше неё.

### Что показала разведка Bonsai

На том же телефоне отдельно проверили `bonsai-1.7b-q1`: один UI-прогон с CPU `Auto (5)` и выключенным GPU toggle дал 47,9 tok/s, один прогон после включения GPU toggle перед перезагрузкой — 19,2 tok/s. Это не GPU-бенчмарк: параметры генерации между ними не фиксировались, а фактический backend не трассировался. Наблюдения опубликованы, чтобы было видно: высокие 145,7 tok/s — результат удачной связки компактной LFM и сценария, а не универсальное свойство любого файла из каталога.

Полный [отчёт LFM2.5](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-lfm230-q4tp-20261001.md) и [машиночитаемая запись](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-lfm230-q4tp-20261001.json) содержат все настройки, счётчики, прогрев и отдельные Bonsai-наблюдения.

## Перевод — отдельная специализированная задача

Для перевода использовался [infosave/Hy-MT2-cmf](https://huggingface.co/infosave/Hy-MT2-cmf). Это другой профиль работы, поэтому его скорость не нужно ставить в один рейтинг с LFM-чатом.

| Вариант | Размер в Hub | Бит/вес в карточке | MT perplexity | Роль |
|---|---:|---:|---:|---|
| `hy-mt2-1.8b-q1t.cmf` | 694,9 MB | 2,25 | 27,88 | Самый компактный вариант |
| `hy-mt2-1.8b-q4tp.cmf` | 950,5 MB | 4,17 | 14,02 | Основной вариант для обычного перевода |

В iPhone-проверке Q4TP после прогрева показала нативную скорость вывода **14,4–21,8 tok/s**, в среднем **17,75 tok/s** по шести тёплым переводам. Полный LAN round-trip от клиента до телефона занимал **0,996–2,015 с**. Это отдельная метрика: она включает сеть, обработку промпта и генерацию.

```text
RU → EN
«Посылка прибудет завтра после 15:00. Пожалуйста, позвоните перед доставкой.»
→ “The package will arrive tomorrow after 15:00. Please call before delivery.”
```

JSON-сценарий EN→DE вернулся валидным: ключи, `count` и плейсхолдеры `{user_name}` / `{order_id}` сохранились. Все семь сценариев, ответы и неокруглённые времена — в [iPhone Q4TP-отчёте](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-hymt2-q4tp-20261001.md) и [JSON](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-hymt2-q4tp-20261001.json).

## CMF: модель описана ещё до загрузки

В основе Cortiq — [CMF](https://github.com/infosave2007/cmf), самоописывающийся контейнер. Помимо весов он несёт архитектуру, токенизатор и сведения о задачах; для моделей с заданным шаблоном — также шаблон чата. Поэтому библиотека показывает квантизацию, число слоёв, контекст и ожидаемую RAM до того, как модель займёт память телефона.

![Ready CMF catalogue in Cortiq Mobile](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/08_ready_cmf_decision.png)

*Ready CMF-каталог: отдельные файлы явно помечены как `Chat` или `Decisions`; рядом видны варианты Hy-MT2.*

| Исходный формат | Путь в приложение |
|---|---|
| Готовый `.cmf` | Скачивание в один шаг; при кратком сетевом обрыве текущая задача докачивает файл с последнего полученного байта. Отменённая или неудачная задача очищает временный файл. |
| Совместимый Hugging Face-репозиторий с `safetensors` | Конвертация в CMF прямо на телефоне; нужны `config.json`, `tokenizer.json` и поддерживаемая архитектура. |
| Поддерживаемый GGUF | Импорт в CMF настольным CLI `cortiq import-gguf`, если формат и архитектура поддержаны importer’ом; затем импорт готового `.cmf` в приложение. |

Так один контейнер используют и мобильное приложение, и Rust-движок на других платформах.

## Decision API: не текст, а исполнимый контракт

CMF умеет не только чат. Decision-модель возвращает структурированный результат: принять вариант или корректно воздержаться.

```json
{"accepted": true, "choice": "card_arrival", "confidence": 0.998}
```

Внешний код исполняет действие только при `accepted == true` и непустом `choice`; кандидат при воздержании не является командой к действию.

![Local CMF Decision accepted on iPhone](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/09_decision_accepted.png)

*На iPhone локальная Decision-модель приняла `card_arrival`, показав confidence и тайминги выполнения.*

### Короткий нагрузочный тест API на Android

Это отдельное измерение: **Xiaomi / Android 14**, а не iPhone. Проверялись контракт API, ограничение очереди и обработка ошибок; точность Decision-модели и долговременная надёжность оно не оценивает. Пройдены **22 из 22** функциональных проверок: health, модели, навыки, решение, воздержание, корректные 401/400/404/409 и восстановление после ошибок.

| Клиентов | Запросов | HTTP 200 / 429 | Успешных решений/с | HTTP p50 / p95 |
|---:|---:|---:|---:|---:|
| 1 | 180 | 180 / 0 | 13,6 | 63 / 137 мс |
| 4 | 128 | 128 / 0 | 27,4 | 135 / 209 мс |
| 16 | 128 | 22 / 106 | 25,9 для успешных | 309 / 361 мс для успешных |

При 16 клиентах сервер отдавал 429 вместо бесконечной очереди. В этом Android-тесте рабочим режимом оказались 1–4 клиента и повтор 429 с задержкой.

## Локально — значит с ясными границами

В обычном локальном режиме, без включённых Companion и Oracle, чат, перевод и Decision исполняются на телефоне. Сеть появляется только в выбранных пользователем сценариях:

| Сценарий | Где обрабатываются данные | Сетевая граница |
|---|---|---|
| Чат, перевод, Decision с загруженной моделью | На телефоне | Удалённый инференс не требуется |
| Скачивание/конвертация модели | Телефон + Hugging Face | Запрос к Hub и файл модели |
| Локальный API | Телефон | Клиенты в выбранной LAN |
| Companion | Телефон + спаренный компьютер | Обмен между этими устройствами |
| Optional Oracle | Выбранный HTTPS-провайдер | Только после ручного включения и подтверждения |

![Optional Oracle is off by default](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/12_oracle_off.png)

*Optional Oracle выключен по умолчанию; внешний клиент не может включить его через API телефона.*

Локальный сервер работает по HTTP без TLS: включите bearer-токен **до** запуска, не публикуйте адрес телефона в интернет и после смены авторизации перезапустите listener. Companion расширяет доступную память, но передаёт данные между устройствами на каждом токене; используйте только доверенную сеть или кабель и одну и ту же модель на обеих сторонах.

## Как выбрать режим

1. **Нужен быстрый короткий ответ.** `lfm2.5-230m-q4tp`: медиана 145,7 tok/s в описанном чат-сценарии на iPhone 16.
2. **Нужен перевод.** `hy-mt2-1.8b-q4tp`: отдельная специализированная модель и явный целевой язык в запросе.
3. **Нужен личный чат с текстом.** Совместимая чат-модель, заранее скачанная на устройство, и текстовое вложение до 512 KiB.
4. **Нужен API для ноутбука.** Bearer-токен, ручной запуск сервера и только доверенная LAN.
5. **Нужно решение, а не свободный текст.** Decision API; воздержание обрабатывается как штатный результат.

## Итог

Cortiq Mobile — уже рабочий личный AI-узел: компактная LFM2.5 показала медиану **145,7 tok/s** в чат-UI на iPhone 16, Hy-MT2 прошла отдельную переводческую проверку, а Decision API — проверку очереди и ошибок на Android. Чат, документы, LAN API и типизированные решения доступны как переключаемые режимы без обязательного удалённого инференса.

Цифры принадлежат указанным устройствам, моделям и сценариям. Для длинного контекста, автономности и критичных текстов нужен собственный профиль тестов; для повседневных локальных задач результат уже можно использовать.
