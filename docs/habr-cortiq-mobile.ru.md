# Локальный AI на iPhone: 145,7 tok/s на LFM2.5 230M в Cortiq Mobile

Локальный AI на телефоне становится рабочим инструментом тогда, когда модель можно выбрать под задачу, а результат — встроить в привычный процесс. В Cortiq Mobile это пять практических сценариев: быстрый чат, перевод, работа с текстовыми вложениями, Chat API для ноутбука и Decision API для автоматизации.

Ниже раздельно приведены iPhone-проверки чата и перевода на **iPhone 16 (A18)** с TestFlight-сборкой **1.3.0 (47)**, а для Decision API — отдельный Android-тест очереди и ошибок. Компактная `lfm2.5-230m-q4tp` в трёх тёплых прогонах показала **144,5–166,0 tok/s**, медиана — **145,7 tok/s**. Это показатель, который Cortiq показывает для конкретной генерации в чате. Переключатель GPU был выключен, пул CPU — `Auto (5)`.

Практический эффект заметен сразу: короткий локальный ответ появляется в темпе интерфейса. После загрузки соответствующей модели обычный чат, перевод или Decision работают без обязательного удалённого inference endpoint — пока пользователь сам не включает Companion или Oracle.

## Пять рабочих сценариев, два разных API

**1. Быстрый локальный чат.** Загрузите небольшую чат-модель — например, LFM2.5 230M — и получите потоковый ответ с показателями задержки, входных и выходных токенов, `tok/s`.

**2. Перевод без обязательного облака.** Отдельная Hy-MT2 1.8B работает на устройстве после загрузки модели. В проверке были RU, EN, DE, TR и ZH.

**3. Диалог с текстовыми вложениями.** Совместимая чат-модель с шаблоном чата и контекстом от 2048 токенов принимает текстовые файлы до 512 KiB: `txt`, `md`, код, JSON и другие текстовые форматы. Файл становится частью контекста, а не отдельной облачной функцией.

**4. Chat API для ноутбука.** После ручного запуска сервера с загруженной чат-моделью доступны OpenAI-совместимые `/v1/chat/completions`, `/v1/completions` и `/v1/models`. Это путь для внешнего клиента, которому нужен сгенерированный текст; в приложении есть QR-код адреса, журнал запросов и bearer-аутентификация.

**5. Decision API для автоматизации.** После ручного запуска сервера с загруженной CMF Decision-моделью доступны `POST /v1/decide` для простого решения, `POST /v1/decisions` для типизированного контракта `state` + `questions` и `GET /v1/skills` для выбора навыка. Вместо свободного ответа программа получает данные для детерминированной ветки workflow.

| Нужен результат | Активная модель | Контракт ответа |
|---|---|---|
| Свободный ответ для человека или внешнего клиента | Чат-модель | OpenAI-совместимый Chat API, текст |
| Действие в автоматизации | Decision-модель | `POST /v1/decide`: `accepted`, `choice`, `confidence` или воздержание; для сложного контракта — `state` + `questions` |

Это не два названия одного API: Chat API обслуживает генеративную чат-модель, а Decision API — модель решений с другим контрактом. В памяти активна одна модель; генеративные и Decision POST-маршруты для неё взаимоисключающие, а `/v1/models` остаётся общим информационным маршрутом.

## 145,7 tok/s в чат-UI: воспроизводимое измерение

Скорость полезна только вместе с устройством, моделью и сценарием. Поэтому условия замера зафиксированы полностью.

| Параметр | Наблюдение |
|---|---|
| Устройство и сборка | iPhone 16 (A18), TestFlight 1.3.0 (47) |
| Модель | `lfm2.5-230m-q4tp`, 126 MiB, 14 слоёв |
| Три тёплых прогона | **144,5**, **145,7**, **166,0 tok/s** |
| Медиана | **145,7 tok/s** |
| Настройки | `temperature: 0.10`, `top_p: 0.95`, `max_tokens: 128`, CPU `Auto (5)`, GPU toggle off |

Методика проста: новый пустой чат, встроенный запрос `Explain how CMF task masks work`, один прогрев и три `regenerate` в одной UI-сессии. Интерфейс показывал семь токенов входа на каждом наблюдении.

`tok/s` — это токены ответа, делённые на полный интервал выполнения, который движок измеряет после старта генерации. В интервал входят обработка промпта и ответ модели, но не ожидание в очереди. Задержку UI округляет, а `tok/s` рассчитывается по неокруглённому таймеру. Получается замер работы реального чат-интерфейса, а не синтетическая цифра декодера.

Для короткого диалога мы используем **60 tok/s** как практическую отметку отзывчивости. Все три тёплых прогона LFM оказались выше неё более чем вдвое.

Полный [отчёт LFM2.5](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-lfm230-q4tp-20261001.md) и [машиночитаемая запись](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-lfm230-q4tp-20261001.json) содержат настройки, счётчики, прогрев и все наблюдения.

## Перевод — отдельный специализированный режим

Для перевода использовался [infosave/Hy-MT2-cmf](https://huggingface.co/infosave/Hy-MT2-cmf). Это не уменьшенная версия чата, а модель для перевода; поэтому у неё свой профиль скорости и свой критерий полезности.

| Вариант | Размер в Hub | Бит/вес в карточке | MT perplexity | Роль |
|---|---:|---:|---:|---|
| `hy-mt2-1.8b-q1t.cmf` | 694,9 MB | 2,25 | 27,88 | Самый компактный вариант |
| `hy-mt2-1.8b-q4tp.cmf` | 950,5 MB | 4,17 | 14,02 | Основной вариант для обычного перевода |

На iPhone Q4TP после прогрева показала нативную скорость вывода **14,4–21,8 tok/s**, в среднем **17,75 tok/s** по шести тёплым переводам. Полный LAN round-trip от клиента до телефона занимал **0,996–2,015 с**.

В базовой проверке все семь коротких запросов вернули непустой результат с `finish_reason: stop`: RU→EN, EN→RU, DE→RU, TR→RU, ZH→EN, перевод идиомы и JSON EN→DE. JSON-сценарий сохранил ключи, `count` и плейсхолдеры `{user_name}` / `{order_id}`.

```text
RU → EN
«Посылка прибудет завтра после 15:00. Пожалуйста, позвоните перед доставкой.»
→ “The package will arrive tomorrow after 15:00. Please call before delivery.”
```

Все семь входов, полные ответы и неокруглённые времена — в [iPhone Q4TP-отчёте](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-hymt2-q4tp-20261001.md) и [JSON](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/reports/iphone-hymt2-q4tp-20261001.json).

## CMF: модель описана ещё до загрузки

В основе Cortiq — [CMF](https://github.com/infosave2007/cmf), самоописывающийся контейнер. Помимо весов он несёт архитектуру, токенизатор и сведения о задачах; для моделей с заданным шаблоном — также шаблон чата. Поэтому библиотека показывает квантизацию, число слоёв, контекст и ожидаемую RAM до того, как модель займёт память телефона.

![Ready CMF catalogue in Cortiq Mobile](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/08_ready_cmf_decision.png)

*Ready CMF-каталог: отдельные файлы явно помечены как `Chat` или `Decisions`; рядом видны варианты Hy-MT2.*

| Исходный формат | Путь в приложение |
|---|---|
| Готовый `.cmf` | Скачивание в один шаг; при кратком сетевом обрыве текущая задача докачивает файл с последнего полученного байта. Отменённая или неудачная задача очищает временный файл. |
| Совместимый Hugging Face-репозиторий с `safetensors` | Конвертация в CMF прямо на телефоне; нужны `config.json`, `tokenizer.json` и поддерживаемая архитектура. |
| Поддерживаемый GGUF | Импорт в CMF настольным CLI `cortiq import-gguf`, если формат и архитектура поддержаны importer’ом; затем импорт готового `.cmf` в приложение. |

Так один контейнер используют и мобильное приложение, и Rust-движок на других платформах.

## Decision API: решение как исполнимый контракт

Пятый сценарий — не ещё одна вариация чата. Простой `POST /v1/decide` возвращает структурированный результат: принять вариант или корректно воздержаться.

```json
{"accepted": true, "choice": "card_arrival", "confidence": 0.998}
```

Внешний код исполняет действие только при `accepted == true` и непустом `choice`; при воздержании он выбирает безопасную ветку workflow или передаёт задачу человеку. Это убирает эвристику разбора свободного текста из автоматизации.

### Нагрузочный тест Decision API на Android

Нагрузочное измерение выполнено отдельно на **Xiaomi / Android 14**. Его цель — проверить контракт API, ограничение очереди и обработку ошибок; iPhone-замер выше относится к чат-модели. Пройдены **22 из 22** функциональных проверок: health, модели, навыки, решение, воздержание, корректные 401/400/404/409 и восстановление после ошибок.

| Клиентов | Запросов | HTTP 200 / 429 | Успешных решений/с | HTTP p50 / p95 |
|---:|---:|---:|---:|---:|
| 1 | 180 | 180 / 0 | 13,6 | 63 / 137 мс |
| 4 | 128 | 128 / 0 | 27,4 | 135 / 209 мс |
| 16 | 128 | 22 / 106 | 25,9 для успешных | 309 / 361 мс для успешных |

При 16 клиентах сервер возвращал 429 вместо бесконечного накопления очереди. Для интеграций рабочий режим в этом тесте — 1–4 клиента и повтор 429 с задержкой. Полный [протокол Android-теста](https://github.com/infosave2007/cmfmobile/blob/7c7333ced7932341e6a36d5530a0177bd99c0607/reports/mobile-1.3.0/GATEWAY_RU.md) содержит условия и исходные JSON серий.

## Локально — значит с ясными границами

В обычном локальном режиме, без включённых Companion и Oracle, чат, перевод и Decision исполняются на телефоне. Сеть появляется только в выбранных пользователем сценариях:

| Сценарий | Где обрабатываются данные | Сетевая граница |
|---|---|---|
| Чат, перевод, Decision с загруженной моделью | На телефоне | Удалённый инференс не требуется |
| Скачивание/конвертация модели | Телефон + Hugging Face | Запрос к Hub и файл модели |
| Локальный API | Телефон | Клиенты в выбранной LAN |
| Companion | Телефон + спаренный компьютер | Обмен между этими устройствами |
| Optional Oracle | Выбранный HTTPS-провайдер | Только после ручного включения и подтверждения |

![Optional Oracle is off by default](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/b068e8d453df94b9ecda8349cf996b7c022910f0/assets/12_oracle_off.png)

*Optional Oracle выключен по умолчанию; внешний клиент не может включить его через API телефона.*

Локальный сервер работает по HTTP без TLS: включите bearer-токен **до** запуска, не публикуйте адрес телефона в интернет и после смены авторизации перезапустите listener. Companion расширяет доступную память, но передаёт данные между устройствами на каждом токене; используйте только доверенную сеть или кабель и одну и ту же модель на обеих сторонах.

## Как выбрать режим

1. **Нужен быстрый короткий ответ.** `lfm2.5-230m-q4tp`: медиана 145,7 tok/s в описанном чат-сценарии на iPhone 16.
2. **Нужен перевод.** `hy-mt2-1.8b-q4tp`: специализированная модель и явный целевой язык в запросе.
3. **Нужен личный чат с текстом.** Совместимая чат-модель, заранее скачанная на устройство, и текстовое вложение до 512 KiB.
4. **Нужен свободный текст из ноутбука.** Chat API, bearer-токен, ручной запуск сервера и только доверенная LAN.
5. **Нужно решение, а не свободный текст.** Decision-модель и Decision API; воздержание обрабатывается как штатный результат.

## Итог

Cortiq Mobile — практический локальный AI-узел с пятью разными сценариями. Компактная LFM2.5 показала медиану **145,7 tok/s** в чат-UI на iPhone 16, Hy-MT2 прошла семь коротких переводческих задач, а Decision API — проверку очереди и ошибок на Android. Чат, документы, локальная интеграция и типизированные решения доступны на одном телефоне без обязательного удалённого инференса.

Ключевой вопрос теперь не «можно ли запустить модель на смартфоне», а какую локальную модель и какой контракт выбрать для конкретной задачи. Для повседневных локальных сценариев это уже можно использовать: открыть приложение, выбрать режим и получить результат на устройстве.
