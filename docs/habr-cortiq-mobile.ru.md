# Локальный AI на iPhone: LFM2.5 230M Q4TP даёт 145,7 tok/s в Cortiq Mobile

Локальная модель на телефоне перестала быть «посмотрите, оно запустилось». В Cortiq Mobile смартфон одновременно становится местом для инференса, офлайн-переводчиком, приватным чатом с документами и небольшим OpenAI-совместимым API в своей сети.

Мы проверили это на подключённом **iPhone 16 (A18)** с TestFlight-сборкой **1.3.0 (47)**. Компактная `lfm2.5-230m-q4tp` в трёх тёплых прогонах выдала **144,5–166,0 tok/s**, медиана — **145,7 tok/s**. Это не лабораторный «decode-only» счётчик: это цифра, которую показывает чат самого приложения для полного пользовательского запроса. Переключатель GPU был выключен, пул CPU — `Auto (5)`.

![LFM2.5 230M Q4TP on iPhone — 162.1 tok/s in the Cortiq chat](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/assets/15_lfm230_iphone_speed.png)

*Реальный экран iPhone: интерфейс показывает `lfm2.5-230m-q4tp`, 95 токенов ответа, 0,6 с и 162,1 tok/s. Задержка в UI округлена.*

Скорость не универсальна для любого файла из каталога — она относится к этой компактной LFM-конфигурации. Зато она показывает важную практическую вещь: для коротких локальных ответов телефон уже не обязательно ждёт модель; модель отвечает в темпе интерфейса.

**Приложение:** [Google Play](https://play.google.com/store/apps/details?id=ai.cortiq.cmf_mobile) · **исходный код 1.3.0:** [infosave2007/cmfmobile](https://github.com/infosave2007/cmfmobile/tree/v1.3.0) · **английская страница со свежими скриншотами:** [Hugging Face Space](https://huggingface.co/spaces/infosave/cortiq-mobile)

> Материал подготовлен командой Cortiq. Замеры, версии моделей и сырые наблюдения опубликованы в конце статьи. iPhone-результаты и снимки относятся к TestFlight 1.3.0 (47); ссылка Google Play ведёт на публичную Android-страницу.

## Что умеет телефон

### 1. Перевод без обязательного удалённого инференса

`Hy-MT2 1.8B` — отдельная переводческая модель. В варианте Q4TP она на iPhone 16 прошла семь коротких сценариев перевода между RU, EN, DE, TR и ZH: после прогрева **14,4–21,8 tok/s**, в среднем **17,75 tok/s**, а полный короткий запрос занимал **0,996–2,015 с**. Модель живёт на устройстве; после скачивания ей не нужен облачный endpoint для генерации перевода.

### 2. Чат с документами и видимой телеметрией

К сообщению можно приложить `txt`, `md`, код или JSON. Чат выводит потоковый ответ, Markdown, историю тем и статистику каждого сообщения: задержку, число токенов входа/выхода и `tok/s`. Это полезнее абстрактного индикатора «печатает»: сразу видно, какую цену имеет конкретная модель и конкретный запрос.

### 3. API, которое лежит в кармане

После ручного запуска сервера с загруженной чат-моделью телефон предоставляет в доверенной LAN `/v1/chat/completions`, `/v1/completions` и `/v1/models`. Ноутбук подключается привычным OpenAI-совместимым клиентом к телефону; в приложении есть QR-код адреса, журнал запросов и bearer-аутентификация. Для CMF Decision доступны типизированные `/v1/decide`, `/v1/decisions` и `/v1/skills`.

## Скорость: модели действительно ведут себя по-разному

Главный новый результат — не «приложение всегда даёт 145 tok/s», а возможность выбрать модель под задачу. В этом тесте компактная LFM2.5-230M быстро отвечает на короткие англоязычные запросы; Hy-MT2 используется для перевода; Decision возвращает типизированный выбор, а не чат-текст. Это результаты разных режимов, а не единый рейтинг моделей.

| Модель и режим | Нагрузка | Что измерялось | Результат | Практический вывод |
|---|---|---|---:|---|
| `lfm2.5-230m-q4tp`, CPU `Auto (5)`, GPU toggle off | компактный общий чат | UI: токены ответа / полное время запроса | **144,5–166,0 tok/s**, медиана **145,7**; 3/3 тёплых прогона выше 60 | Быстрый локальный режим для коротких англоязычных запросов |
| `lfm2.5-230m-q4tp`, отдельный интерактивный запрос | общий чат | UI: тот же показатель | **162,1 tok/s** на экране выше | Наглядное подтверждение в UI |
| `bonsai-1.7b-q1`, CPU `Auto (5)`, GPU toggle off | Chat UI, generic ChatML fallback | UI: отдельный разведочный прогон | 47,9 tok/s | В единственном наблюдении ниже цели 60 tok/s |
| `bonsai-1.7b-q1`, GPU toggle включён до перезагрузки | Chat UI, generic ChatML fallback | UI: отдельный разведочный прогон; backend не трассировался | 19,2 tok/s | Наблюдение после включения toggle, не GPU-бенчмарк |
| `hy-mt2-1.8b-q4tp`, CPU `Auto (5)`, GPU toggle off | короткий перевод | native output rate; backend не трассировался; полное LAN-время — отдельно | в среднем **17,75 tok/s** по шести тёплым переводам | Специализированный режим перевода |

Для LFM получились три повторных тёплых наблюдения в одной UI-сессии: новый пустой чат, встроенный запрос `Explain how CMF task masks work`, один прогрев и три повтора через regenerate; `temperature: 0.10`, `top_p: 0.95`, `max_tokens: 128`. Интерфейс показывал семь токенов входа для каждого прогона. Его `tok/s` включает обработку запроса, поэтому это консервативная, пользовательская цифра, а не завышенная скорость чистого декодера.
Строки не образуют одну шкалу производительности: LFM измерена по счётчику чат-UI, Hy-MT2 — по нативной скорости вывода на специализированной переводческой задаче; полное LAN-время для неё опубликовано отдельно. Два Bonsai-прогона — первичная разведка в Chat UI с generic ChatML fallback: их отдельные параметры генерации не зафиксированы, а эффект GPU toggle не подтверждён серией. Эти числа помогают выбрать направление проверки, а не ранжировать модели по одному числу.

Полный [отчёт LFM2.5](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/reports/iphone-lfm230-q4tp-20261001.md) и [машиночитаемая запись](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/reports/iphone-lfm230-q4tp-20261001.json) содержат все видимые счётчики, настройки, прогрев, диапазон и отдельные Bonsai-прогоны.

### Почему 230M-модель здесь уместна

`lfm2.5-230m-q4tp.cmf` занимает **126 MiB** в карточке Cortiq, содержит 14 слоёв и до загрузки оценивается примерно в **622 MiB RAM**. Это другой класс модели, не попытка назвать её «маленькой универсальной заменой всему». Её сильная сторона — скорость и компактность; для содержательной многоязычной работы выбирается специализированная модель, а для критичного результата остаётся проверка в предметном контексте.

Именно поэтому результат выше ценнее красивой средней цифры по каталогу: пользователь видит, какую модель брать, если нужна скорость, а какую — если нужен перевод.

## Перевод: Q4TP вместо экономии любой ценой

Для перевода использовался [infosave/Hy-MT2-cmf](https://huggingface.co/infosave/Hy-MT2-cmf). В каталоге есть две полезные квантизации:

| Вариант | Размер в Hub | Бит/вес в карточке | MT perplexity | Роль |
|---|---:|---:|---:|---|
| `hy-mt2-1.8b-q1t.cmf` | 694,9 MB | 2,25 | 27,88 | Самый компактный вариант |
| `hy-mt2-1.8b-q4tp.cmf` | 950,5 MB | 4,17 | 14,02 | Основной вариант для обычного перевода |

В iPhone-тесте Q4TP дал среднюю нативную скорость **17,75 tok/s** по шести тёплым переводам. При оценке памяти порядка 1,5 GiB RAM Q4TP — разумный выбор, если телефон его вмещает.

```text
RU → EN
«Посылка прибудет завтра после 15:00. Пожалуйста, позвоните перед доставкой.»
→ “The package will arrive tomorrow after 15:00. Please call before delivery.”
```

JSON-сценарий EN→DE тоже вернулся валидным: ключи, `count` и плейсхолдеры `{user_name}` / `{order_id}` сохранились. Все семь входов, ответы и неокруглённые времена опубликованы в [iPhone Q4TP-отчёте](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/reports/iphone-hymt2-q4tp-20261001.md) и [JSON](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/reports/iphone-hymt2-q4tp-20261001.json).

## CMF: каталог объясняет модель до загрузки

В основе Cortiq — [CMF](https://github.com/infosave2007/cmf), самоописывающийся контейнер. Помимо весов в нём лежат архитектура, токенизатор и сведения о задачах; для моделей с заданным шаблоном — также шаблон чата. Пользователь получает не безымянный файл, а карточку с квантизацией, слоями, контекстом и ожидаемой RAM.

![Ready CMF catalogue in Cortiq Mobile](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/assets/08_ready_cmf_decision.png)

*Ready CMF-каталог: отдельные файлы явно помечены как `Chat` или `Decisions`; рядом видны варианты Hy-MT2.*

Практические следствия просты:

- готовый `.cmf` скачивается одним действием, а прерванная загрузка продолжается с последнего байта;
- перед запуском видна оценка RAM, а не только размер архива;
- поддерживаемый репозиторий Hugging Face с safetensors конвертируется в CMF прямо на телефоне; GGUF CMF toolchain импортирует через `cortiq import-gguf`, после чего готовый `.cmf` можно перенести в приложение;
- один контейнер понимают мобильное приложение и Rust-движок на других платформах.

## Decision API: не текст, а исполнимый контракт

CMF описывает не только чат. Для CMF Decision приложение возвращает типизированный результат — принять вариант или корректно воздержаться. Это удобно в автоматизации, где свободный текст «похоже, надо сделать X» хуже формального контракта.

```json
{"accepted": true, "choice": "card_arrival", "confidence": 0.998}
```

![Local CMF Decision accepted on iPhone](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/assets/09_decision_accepted.png)

*На iPhone локальная Decision-модель приняла `card_arrival`, показав confidence и тайминги выполнения.*

Если уверенности нет, API возвращает `accepted: false`. Внешний код исполняет действие только при `accepted == true` и непустом `choice`; кандидат при воздержании — не команда к действию.

Отдельный нагрузочный тест запускался на **Xiaomi / Android 14**, а не на iPhone: он проверял телефон как API-шлюз. Пройдены **22 из 22** функциональных проверок — health, модели, навыки, решение, воздержание, корректные 401/400/404/409 и восстановление после ошибок.

| Параллельных клиентов | Запросов | HTTP 200 / 429 | Успешных решений/с | HTTP p50 / p95 |
|---:|---:|---:|---:|---:|
| 1 | 180 | 180 / 0 | 13,6 | 63 / 137 мс |
| 4 | 128 | 128 / 0 | 27,4 | 135 / 209 мс |
| 16 | 128 | 22 / 106 | 25,9 для успешных | 309 / 361 мс для успешных |

При 16 клиентах API отдавал 429 вместо бесконечной очереди. Рабочий режим для интеграции — 1–4 клиента и повтор 429 с задержкой. Эти числа характеризуют контракт, очередь и сеть Android-шлюза, а не точность Decision-модели и не скорость iPhone.

## Локально — значит с ясными границами

В обычном локальном режиме — без включённых Companion и Oracle — чат, Hy-MT2-перевод и Decision исполняются на устройстве. Сеть появляется только там, где она нужна пользователю:

| Сценарий | Где данные обрабатываются | Сетевая граница |
|---|---|---|
| Чат, перевод, Decision с загруженной моделью | На телефоне | Удалённый инференс не требуется |
| Скачивание/конвертация модели | Телефон + Hugging Face | Запрос к Hub и файл модели |
| Локальный API | Телефон | Клиенты в выбранной LAN |
| Companion | Телефон + спаренный компьютер | Обмен между этими устройствами |
| Optional Oracle | Выбранный HTTPS-провайдер | Только после ручного включения и подтверждения |

![Optional Oracle is off by default](https://huggingface.co/spaces/infosave/cortiq-mobile/resolve/fc4d4ff0d4c0121544c662fc8490b3cc7d915e07/assets/12_oracle_off.png)

*Optional Oracle выключен по умолчанию; внешний клиент не может включить его через API телефона.*

Companion помогает вместить модель, разделяя её исполнение со спаренным компьютером. Это путь к большей памяти, а не обещание бесплатного ускорения: между устройствами есть обмен на каждом токене. Локальный сервер рассчитан на доверенную сеть: включайте bearer-токен до запуска и не публикуйте HTTP-адрес телефона в интернет.

## Как использовать Cortiq на практике

1. **Нужен быстрый локальный ответ на короткий запрос.** Берите `lfm2.5-230m-q4tp`: этот сценарий уже показал 145,7 tok/s медианы в UI на iPhone 16.
2. **Нужен перевод.** Берите `hy-mt2-1.8b-q4tp`, указывайте целевой язык и просите вернуть только перевод.
3. **Нужны документы и личный чат.** Скачайте модель заранее, прикрепляйте текст, код или JSON и работайте без обязательного удалённого инференса.
4. **Нужен API для ноутбука.** Включите bearer-токен, поднимите сервер только в своей LAN и используйте обычный OpenAI-совместимый клиент.
5. **Нужно решение, а не ответ текстом.** Используйте Decision API и обрабатывайте воздержание как штатный результат.

## Итог

Cortiq Mobile уже можно описывать не как эксперимент, а как личный AI-узел с понятными режимами работы. На одном телефоне есть быстрый локальный чат, рабочий перевод, документы, LAN API и типизированные решения. Результаты привязаны к своим режимам: LFM2.5 показала медиану **145,7 tok/s** в чат-UI на iPhone, Hy-MT2 прошла отдельный переводческий тест, а Decision API — отдельную нагрузочную проверку на Android.

Измерения привязаны к устройству, модели и короткому сценарию; для длинного контекста, автономности и критичных текстов нужен свой профиль тестов. Но для повседневных локальных задач это уже не обещание будущего, а работающий инструмент.
