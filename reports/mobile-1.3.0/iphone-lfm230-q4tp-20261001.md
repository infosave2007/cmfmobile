# LFM2.5 230M Q4TP on iPhone 16 — interactive throughput report

* **Date:** 2026-10-01
* **Device:** iPhone 16 (A18)
* **App:** Cortiq Mobile TestFlight `1.3.0 (47)`
* **Model:** `lfm2.5-230m-q4tp.cmf` from [infosave/LFM2.5-cmf](https://huggingface.co/infosave/LFM2.5-cmf)
* **Model file:** 132,082,125 bytes (126 MiB in the app); Hub LFS SHA-256 `889fa1e3a133004f9fab273e24a355b51056c5e349f9efd4552892a440c42f9a`
* **App estimate before loading:** about 622 MiB RAM, 14 layers, 128K context

## Result

With the app's GPU toggle **off** and its CPU pool at **Auto (5)**, three warm
interactive completions measured in the phone UI at **144.5–166.0 tok/s**;
the median was **145.7 tok/s**.  This is the app's end-to-end, user-visible
rate, rather than a synthetic core-only decode number.

The separate public UI capture in the Space, `assets/15_lfm230_iphone_speed.png`,
shows another interactive LFM completion at **162.1 tok/s**.

## Method

1. The Ready CMF file was downloaded and loaded locally in the TestFlight app.
2. A new empty conversation was created. The built-in English suggestion
   `Explain how CMF task masks work` was used unchanged; the app displayed
   seven prompt tokens for every observed run.
3. The first completion was a warm-up and is reported separately.
4. The next three completions were generated with the UI's regenerate action
   in the same loaded-model session.
5. The UI settings were set to `temperature: 0.10`, `top_p: 0.95`,
   `max_tokens: 128`, `CPU Auto (5)`, and GPU toggle off. The original phone settings
   (`temperature: 0.70`, `top_p: 0.95`, `max_tokens: 1024`, GPU toggle off) and
   MiniCPM5-2B as the active model were restored after testing.

The chat screen reports completion tokens, latency and `tok/s` for every
message. The rate divides returned completion tokens by the full measured
request time, so prompt processing is included. The text of the prompt is a
throughput workload only; it is not a quality evaluation of a 230M model or
of CMF task masks.

`tok/s` readings; no unobserved millisecond precision is implied.

## Other models checked in the same device session

The shipped Bonsai CMF header has no `tokenizer_config.chat_template`, so the
message-based Chat UI uses its generic ChatML fallback template. These two observations use the same
short built-in prompt, but are explicitly exploratory single runs rather than
the controlled three-run LFM series. Their observed completion counts exceed
the LFM cap of 128, so the LFM sampling and generation-cap configuration did
not apply; its exact separate setting was not recorded. They are not a
controlled comparison with LFM:

| Model / setting | Completion tokens (UI) | UI tok/s | Reading |
|---|---:|---:|---|
| `bonsai-1.7b-q1.cmf`, CPU Auto (5), GPU toggle off | 541 | 47.9 | Generic ChatML fallback template; below the 60 tok/s target in this one observation. |
| `bonsai-1.7b-q1.cmf`, GPU toggle on before reload | 261 | 19.2 | First run after enabling the toggle; backend was not traced and the result is not used for the headline. |

For comparison of a different task class, the existing
[Hy-MT2 Q4TP iPhone report](iphone-hymt2-q4tp-20261001.md) measured short
translation requests at a mean **17.75 tok/s** after warm-up. Translation,
compact general chat, and the Decision API are different workloads; their
numbers are shown side by side for model selection, not as a quality ranking.

## Scope

This is a real-device responsiveness check for a small local model. It does
not measure long contexts, battery use, sustained thermals, tokenization
accuracy, or task quality. Results belong to this iPhone, this TestFlight
build, the stated model, settings and prompt. The high-throughput result is a
property of this LFM2.5 230M configuration, not a promise for every model in
the catalog.
