# Телефон как шлюз CMF Decision — реальные проверки

**Вывод:** для персонального шлюза в доверенной Wi-Fi-сети — рабочий вариант.
Для публичного API или автономного сервера 24/7 текущую версию рекомендовать рано.

Телефон: Xiaomi 2203129G, Qualcomm SM7325, Android 14, около 7 ГиБ доступной
ОС физической памяти. Клиент — Mac по настоящему Wi-Fi, **не ADB port-forward**.
Приложение 1.3.0-dev / 47 из GitHub CI, нативный release-runtime 0.8.0, CPU.
Сеть, JSON, очередь и вычисление включены в HTTP-время. Это короткий тест,
а не суточная нагрузка или измерение предельной мощности телефона.

## Что прошло

**22 из 22 проверок:** health, список моделей, три навыка и их рубрики,
`/v1/decide`, `/v1/decisions`, `/api/alpha/decisions`, принятие решения и отказ,
401 без ключа/с неправильным ключом, 400 для повреждённого JSON и неверных
параметров, 404 для неизвестного навыка, 409 для чата при Decision-модели.
После ошибок правильный запрос снова даёт правильное решение.

Удалённый клиент **не может включить оракул** и расходовать его ключ.
В успешных параллельных ответах не перепутаны навыки или результаты;
идентификаторы ответов уникальны. Оракул и кэш выключены.

## Измерения

Три короткие контрольные фразы чередовались между BANKING77, CLINC150 и MASSIVE.
Перед каждой серией — 15 прогревочных запросов. Повторение этих фраз проверяет
работу API и нагрузку, **не точность модели на новых данных**.

| Клиентов | Запросов | HTTP 200 / 429 | Успешных решений/с | HTTP p50 / p95 |
|---|---:|---:|---:|---:|
| 1 | 180 | 180 / 0 | 13,6 | 63 / 137 мс |
| 4 | 128 | 128 / 0 | 27,4 | 135 / 209 мс |
| 16 | 128 | 22 / 106 | 25,9 | 309 / 361 мс для успешных |

При 16 клиентах ограниченная очередь возвращает **429**, а не растёт без конца.
Увеличение параллельности выше ёмкости телефона не ускоряет вычисления.
Практический старт — **1–4 клиента**, небольшая очередь у вызывающей программы
и повтор 429 с задержкой, а не бесконечный немедленный retry.

Нативное решение в сериях: p50 **21–24 мс**. Это не то же самое, что полное
время HTTP, и не только резонанс. После сворачивания приложения 60/60 запросов
завершились: HTTP p50 **48 мс**, p95 **132 мс**. Снимок памяти с загруженной
Decision-моделью: PSS около **569 МиБ**, RSS **666 МиБ**; не пик.

## Ограничения, которые нельзя скрывать

- **HTTP без TLS.** Только доверенная сеть или защищённый туннель. Включите
  bearer-токен **до старта**. В этой версии изменение настройки авторизации
  не обновляет уже запущенный listener автоматически: после изменения
  остановите и снова включите сервер. Это найдено при проверке кода.
- Фоновая работа проверена короткой серией. Сутки, нагрев, расход батареи,
  переподключение Wi-Fi и восстановление после убийства процесса не проверены.
- Android-сервис использует `dataSync`, а его partial wake lock ограничен
  одним часом. Android 15+ дополнительно ограничивает `dataSync` в фоне
  шестью часами за сутки, с описанными в документации условиями сброса.
  [Правила Android](https://developer.android.com/develop/background-work/services/fgs/timeout).
- На iPhone не проверялось. Обычное iOS-приложение может быть приостановлено
  в фоне; эта реализация не обещает непрерывный iOS-сервер.
  [Правила Apple](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).
- Генеративный SSE проверен отдельно на Hy-MT2: события приходили одним
  пакетом в конце ответа. Это не доказательство плавного поточного вывода.
- Одновременно загружена **одна** модель. Загрузка переводчика или чат-модели
  меняет доступную операцию: решения требуют снова загрузить CMF Decision.

Дополнительно на этом же сервере с загруженной Hy-MT2 короткий перевод
успешно выполнен при погашенном экране. Decision-нагрузка с выключенным
экраном отдельно не измерялась; суточная автономность не подтверждена.

## Подключение

В приложении: **Модели → CMF Decision → Открыть решения → Сервер**.
Включите требование токена, затем сервер. Возьмите адрес и ключ с этого экрана.

```bash
# PHONE_TOKEN задайте локально; не сохраняйте его в исходниках.
curl "http://PHONE_IP:8080/v1/decide" \
  -H "Authorization: Bearer $PHONE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"skill":"banking77","text":"Where is my card?","profile":"balanced"}'
```

Для исполнения действия проверяйте `accepted == true` и непустое `choice`.
`candidate` при отказе — только предположение, не команда к исполнению.

[Исходные проверки](gateway-functional.json), [1 клиент](gateway-wifi-c1.json),
[4 клиента](gateway-wifi-c4.json), [16 клиентов](gateway-wifi-c16.json),
[в фоне](gateway-background.json). Воспроизведение: `scripts/check_phone_gateway.py`.
